# Life Mem

Life Mem 是一个 iPhone 路线记录工具。点「开始记录」，锁屏后可以继续采集。点「暂停记录」即停止采集，并可以回看当前路线。继续记录会开启新的一段。已保存的轨迹可以在「回顾」中按天查看，重新打开 App 后也可以找回中断的记录。

项目的代码职责、数据保护和变更验收约定见 [工程规范](AGENTS.md)。

## 在 iPhone 上测试

1. 用 Xcode 打开 `LifeMem.xcodeproj`。在 **Signing & Capabilities** 为 `LifeMem` 目标选择自己的团队，并启用自动签名。需要时设置唯一的 Bundle ID。
2. 选中已配对且启用了开发者模式的 iPhone，运行 `LifeMem`。App 目标支持 iOS 17 或更新版本。
3. 点「开始记录」，授予使用期间的定位权限并保留精确位置。允许「运动与健身」可以更好地识别步行、骑行和乘车。
4. 锁屏步行一段并中途停留，再解锁、暂停、回看路线。另一次以乘客身份测试乘车，在抵达后比对两种模式和路线覆盖情况。恢复记录后应出现新路线段，关掉 App 再打开应能查到已保存的轨迹。

## 自动记录（试用）

在「记录」页开启「自动记录（试用）」，允许始终定位并开启精确位置，即可锁屏出行。手动路线结束后可以开启试用，关闭试用即可使用手动记录。系统交付的实时位置由同一套采样规则写入本机路线库和回顾。

为减少静置漂移，90 秒内的两个有效位置须相距至少 25 米且达到两点水平精度之和，确认后从第一个位置开始保存。系统报告静止时保存并结束路线。若在 8 分钟内从停下位置附近（100 米内）再次出发，会接回同一条路线并新开一段。较长停留下次出发时另起路线。若系统持续投递位置，低速定位在约 25 米（精度较低时放宽至水平误差）范围内持续 8 分钟也会收尾。iOS 决定锁屏定位的投递时机；试用时可在回顾中核对起点、途中停顿和终点。

## 自适应采样

App 使用系统定位和运动识别，按运动状态设置定位精度与距离门槛。下表是本项目的初始参数。系统按可用的定位信号和设备状态决定何时交付坐标。

| 状态 | 距离门槛 | 记录行为 |
| --- | --- | --- |
| 步行 | 8 米 | 保留较短的移动和转弯 |
| 乘车 | 30 米 | 用较大的距离间隔记录快速移动 |
| 骑行 | 15 米 | 使用介于步行和乘车之间的间隔 |
| 静止 | 无 | 以与移动时相同的目标精度请求定位，停留期间最多每 30 秒保存一个有效定位点，用于显示时间范围 |
| 未识别 | 10 米 | 根据可靠的定位速度尝试分类。系统持续交付近距离样本时，最少间隔 30 秒保留一个不计里程的定位点 |

运动传感器尚未识别或判断为静止时，由 App 应用上表的保存门槛，以便系统仍能交付减速和停下后的样本。速度兜底在高质量样本显示速度持续低于 0.7 米/秒至少 12 秒时判为静止，在速度持续大于 2.8 且低于 7.5 米/秒至少 8 秒时尝试识别骑行。定位已识别为乘车时，先确认停下再尝试识别步行或骑行。

定位点的水平误差必须在 50 米以内。相邻定位推算速度超过 200 公里/小时会被过滤，步行和骑行保留更低的模式上限。暂停和有效坐标相隔超过 90 秒都会切开观测。旧版本记录的定位点会在回顾时按同样的精度和通用速度上限清理。

## 回顾

- 「时间线」按设备日历汇总已记录的日期。跨午夜的连续移动会在地图上分日显示，时间线和摘要按同一个午夜分摊里程与耗时。点进某天可以看记录跨度、移动里程、移动耗时和各类停留。地图用绿色虚线表示步行、橙色表示骑行、蓝色表示乘车。点停留气泡会滚动到时间线卡片，点时间线卡片会聚焦对应位置或路段。选中混合行程后可以展开「移动片段」。暂停恢复或有效坐标相隔超过 90 秒时，地图按原有分段留出断口。
- 「地点」汇总至少连续观测 8 分钟、定位点落在起点 60 米内且没有明确运动状态的停留。停留位置按定位精度加权，回顾时不将停留漂移算作出行。相距约 100 米以内的停留合并为一处。跨午夜的停留按午夜分摊时长，在地点里计为一次到访。移动方式优先采用已记录的运动状态，未知时根据相邻点的速度估算步行、骑行或乘车。
- 点选时间线里的行程卡片，在卡片的「地名」里选择起点或终点。可以直接输入名称，或点「查找地名」让系统地图用这个端点的坐标提供附近地点和地址候选。在停留地点或行程端点也可以选择家、工作／学习、餐饮等分类。保存的名称优先显示，并在附近的行程起终点和停留地点复用。编辑地名时，如果文件读取失败，可以重试。文件损坏时，可确认保留原件并重建。
- 「回顾 → 地点」会从本机最近 28 个日期的停留给出「家」和「工作／学习」候选，连续性和次数满足条件时由你确认。
- 第一次在「回顾」看到未命名停留时，可以开启自动地名或稍后在右上角选项里开启。App 会将尚未命名的停留中心坐标交给 Apple 地图。默认标签优先使用 50 米内有明显距离优势的 POI，其次是街道或街区，再用 200 米内的地标或购物中心。编辑地名时可选门牌地址和相邻店铺等候选。确认开启后，App 在前台闲置时也会优先准备近期已结束记录的地名。之前开启过自动地名的用户，可以在菜单里另行确认「提前准备地名」。结果缓存在本机，离线时可以复用。相近地点共用查询，服务暂不可用时会短暂停止新请求。可随时关闭自动地名或清除缓存。

轨迹数据库保存在 App 的本机目录，禁用自动云同步和云备份。地图回看由 Apple MapKit 提供。可在「回顾」右上角打开「管理记录」，向左滑动删除一条原始记录及其各日轨迹。暂停后也可以在「记录」页丢弃当前路线。重开 App 时，最近一条未结束记录会以暂停状态恢复。

地图会自动将中国大陆的轨迹、停留点和地图聚焦位置对齐高德底图。显示地图和查找地名时，设备会将原始坐标从 WGS-84 换算为 GCJ-02。旧版在大陆使用原始坐标查到的自动地名会在下次查找时更新。原始轨迹、里程、手动地名和分类沿用本机存储。覆盖范围取自公共领域数据 [Natural Earth 1:10m Admin 0 Map Units v5.1.2](https://github.com/nvkelso/natural-earth-vector/blob/v5.1.2/geojson/ne_10m_admin_0_map_units.geojson) 中 `GU_A3` 为 `CHN` 的区域，经纬度保留五位小数。

## 分析

「分析」支持本周、本月和自定义日期。「时间分配与记录覆盖」区分观测到的移动、停留和未记录。过去日期按当地自然日结算，今天只统计到当前时刻，未来日期不入图。回顾与分析复用已解析的路线。分析可以从本机每日摘要直接打开，追加、删除或时区变化后会按当前数据刷新。跨午夜的连续移动和停留按午夜分摊，停留在所选范围内算一次到访。「常去地点」可按到访次数或累计停留时长切换排行，最多显示十处。「通行效率」按方向和主要出行方式归纳相近起终点的重复路线，按首次观测到移动的日期和小时归类，展示整趟行程的耗时范围和中位数。「本期洞察」显示首次记录的地点数、居家占已记录时长比例，以及有足够同路线样本时的通勤对比。「常走路线」同时列出本期平均和历史最短、最长耗时。

通勤对比和常走路线使用出发、到达两端均有识别停留的完整行程，并按出发时间归类。「离家与回家」使用和标记为家的停留相连的记录，展示每日首次离家与末次回家。

## 本地检查

在装有完整 Xcode 的 Mac 上，从仓库根目录运行以下命令。如果当前开发者目录指向 Command Line Tools，可以先在当前终端运行 `export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`，并按实际安装位置调整路径。

### 路线回归检查

覆盖地图坐标换算、自适应采样、活动分段、按日切分、中断、停留分组、行程起终点、地名复用和保存，以及重开数据库后的持久性及删除行为。

```sh
mkdir -p DerivedData
xcrun swiftc -parse-as-library \
  LifeMem/{LocationPoint,RouteModels,AutomaticTrips,SegmentBuilder,TimelineSegment,Routes,RouteSummary,SavedPlace,PlaceResolver,PlaceSuggestions,RouteAnalytics,RouteBehavior,RouteInsights,RouteMapProjection}.swift \
  tests/RouteChecks.swift -o DerivedData/route-checks
./DerivedData/route-checks
```

### 模拟器构建

使用共享的 `LifeMem` scheme 检查 iOS App 能否编译。此命令无需启动模拟器或配置签名。

```sh
xcodebuild -project LifeMem.xcodeproj -scheme LifeMem -configuration Debug \
  -destination 'generic/platform=iOS Simulator' \
  -derivedDataPath DerivedData/simulator CODE_SIGNING_ALLOWED=NO build
```

### 回顾界面回归

在已启动的 iPhone 模拟器上运行，使用隔离的临时存储和合成路线。将 `SIMULATOR_ID` 换成 `xcrun simctl list devices booted` 中的模拟器 ID。

自动记录界面用例使用模拟器的始终定位权限。可用上方模拟器构建产物安装并授权。

```sh
xcrun simctl install SIMULATOR_ID DerivedData/simulator/Build/Products/Debug-iphonesimulator/LifeMem.app
xcrun simctl privacy SIMULATOR_ID grant location-always dev.kolafish.lifemem
xcodebuild -project LifeMem.xcodeproj -scheme LifeMem -configuration Debug \
  -destination 'id=SIMULATOR_ID' -derivedDataPath DerivedData/ui-tests \
  -parallel-testing-enabled NO CODE_SIGNING_ALLOWED=NO test
```
